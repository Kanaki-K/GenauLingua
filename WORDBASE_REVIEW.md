# Как вычитывается словарная база

Этот файл отвечает на вопрос **«как это было сделано»** — чтобы в следующий
раз не выдумывать метод заново и чтобы по нему можно было сверяться.

Рядом лежат три других документа, и у каждого своя работа:

| файл | о чём |
|---|---|
| **этот** | метод: как читать, как мерить, как править, в каком порядке |
| `REVIEW_CRITERIA.md` | что считается дефектом |
| `REVIEW_LEDGER.md` | журнал: что нашли в каждом блоке и почему так решили |
| `HANDOVER.md` | состояние работ, открытые решения владельца, выведенные правила |

---

## 1. Что такое база

**12 902 ряда × 6 языков = 77 412 ячеек.** Ряд — это немецкое слово, его
артикль, уровень, частотный ранг, пять переводов и шесть примеров
(по одному на язык).

Немецкий ряд — **эталон**. Пять переводов — его отражения, а не
самостоятельные фразы.

Главное требование владельца, из которого растут все критерии:

> Переводы должны быть **естественными** и **соответствовать друг другу**.
> Без заумных академических слов, по-людски.

## 2. Что сделано: три прохода

| | блоков | правок | плотность |
|---|---|---|---|
| **Проход 1** | 72 | 12 877 | ~225 на 200 рядов |
| **Проход 2** | 65 (вся база) | 1 774 | ~24 на 200 рядов |
| **Проход 3** | 14 (ряды 1–2800) | 224 | ~3 на 200 рядов глазами |

**Итого 14 875 правок.** Все 12 902 ряда прочитаны глазами дважды, первые
2 800 — трижды.

Третий проход был **адресным**, а не сплошным: второй проход читал ранние
блоки слабым набором правил (19 примет и 5 гейтов), а поздние — сильным
(47 и 9). Читалась только та зона, где набор был слабее и где при этом
самая частотная лексика.

**Главный урок третьего прохода.** Из 224 ячеек глазами в блоках найдено
около 40, остальные 180 с лишним — **замерами по всей базе, которые эти
блоки подсказали**. Чтение частотной зоны — самый дешёвый способ найти
КЛАСС, а не способ проверить конкретные ряды.

## 3. Метод: цикл одного блока

```
1. Выгрузить блок:  python -m app.scripts.wordbase_review_block --from N --count 200
2. Прочитать глазами целиком, не по диагонали
3. Любое наблюдение, повторившееся дважды, → ЗАМЕР ПО ВСЕЙ БАЗЕ
4. Написать app/scripts/fix_pass{N}_block_{NN}.py по образцу
5. Сухой прогон → «пропущено 0»
6. --apply → «самопроверка: не записалось 0»
7. Все приметы и гейты → выход 0
8. Гейт целостности → SUM(times_shown)=29742, SUM(times_correct)=26133, рядов 12902
9. python -m app.scripts.verify_wordbase --rounds 1 --size 12902
10. pytest -q
11. Запись в REVIEW_LEDGER.md, указатель в HANDOVER.md
12. Коммит
```

### Почему скрипт правок, а не руками в базе

Каждая правка — кортеж `(id, колонка, было, стало, зачем)`. Поле «было»
работает **стражем**: если в базе лежит не то, что ожидалось, правка
пропускается и это видно в отчёте. Поэтому скрипт можно прогнать дважды,
можно прогнать после чужих изменений, и он не испортит данные молча.

В докстринге скрипта пишется не «что», а **«почему»**: какой класс нашли,
каким замером проверили, что отменили и на каком основании. Через месяц
это единственное, что отличает решение от произвола.

## 4. Приметы и гейты

**48 примет** (`app/scripts/scan_*.py`), из них **10 — гейты**.

* **Гейт** — правило без законных исключений. Любое попадание = дефект,
  выход 1. Например: знак вопроса, чужая буква, немецкое склонение.
* **Примета** — правило с **задокументированным остатком**. Падает, когда
  остаток ИЗМЕНИЛСЯ, а не когда он не ноль.

```bash
# прогнать всё
for f in app/scripts/scan_*.py; do python -m app.scripts.$(basename $f .py); done

# самопроверка правила на размеченных парах
python -m app.scripts.scan_question_mark --selfcheck
```

**Задокументированный остаток — это список нерешённого, а не список
исключений.** Если остаток изменился, разбирают причину и обновляют
докстринг; если правка его увеличила — сперва ищут формулировку без
побочного эффекта.

## 5. Правила замера, выведенные болью

Полный список — в `HANDOVER.md` (пункты 1а…1бу). Пять, которые ломали
работу чаще всего:

1. **Проверь условие отбора на ряде, который ты УЖЕ знаешь как дефектный.**
   Если известный дефект не попал — неверно условие, а не база чиста.
   (Регистрозависимый поиск артиклей спрятал 15 рядов из 18.)

2. **Вывод замера нельзя читать через `tail` или `head`.** Сперва печатай
   ЧИСЛО попаданий, потом строки. (47 попаданий, увидел 18, записал в
   журнал «17» — и класс пришлось добирать два блока спустя.)

3. **Класс, живущий в шести языках, требует шести правил.** Турецкий ставит
   пометку послелогом в конце, а правила искали предлог впереди — и
   турецкая полоса не проверялась ни разу.

4. **Ставь границы слова в самом запросе.** `str.replace("dr", "doktor")`
   превратил «adres» в «adoktores» в 497 рядах.

5. **Когда спрашиваешь «что увидит ученик» — спрашивай КОД, а не текст.**
   Замер по тексту дал 223 подозрительных ряда, замер через `main_meaning`
   — три настоящих.

И один про инструмент: **между списком и правилом выбирай правило**, потому
что список кончается там, где кончилось твоё воображение. Исключение —
когда список кончается в СЛОВАРЕ: род-различающие омографы немецкого
(`der/das Schild`) структурным правилом не найти, там нужно перечисление,
выписанное целиком.

## 6. Карточка: договорённость и как она проверяется

**Одно слово, один пример, один ответ.** На карточке показывается то
значение, которое стоит в примере (`main_meaning`), — оно же произносится,
оно же стоит в названии клипа.

Проверяется не чтением кода, а прогоном по всей базе:

```python
# для каждого ряда × каждой пары языков × каждого направления
_question_text(...)   # в заголовке нет запятой
option_label(...)     # на кнопке нет запятой
_answer_text(...)     # в разборе нет запятой
```

Последняя проверка: **774 120 сочетаний, ноль списков.**

Договорённость закреплена тестами в `tests/test_card_contract.py` и
`tests/test_option_label.py`. Если кто-то сдвинет формат, тест назовёт, что
именно сломалось.

## 7. Озвучка

Движок — `edge_tts`, **бесплатный**. Хранилище — каталог `tts/`, клипы
живут независимо от бота и переносятся копированием.

```bash
python -m app.scripts.tts_synthesize --stats        # что уже есть
python -m app.scripts.tts_synthesize                # досинтезировать недостающее
python -m app.scripts.verify_wordbase --rounds 1 --size 12902   # вся цепочка
python -m app.scripts.tts_asr_check --lang pl --limit 250       # проверка слухом
```

Два вида клипа на слово: **word** (только слово) и **full** (слово и
пример). Имя клипа — хеш произносимого текста, поэтому **правка текста
осиротит клип**, и после каждой правки нужен досинтез.

**Проверка слухом замкнута машинно:** `tts_asr_check` распознаёт
сгенерированный клип через `faster-whisper` и сверяет расшифровку с
исходным текстом. Проверяются клипы С ПРИМЕРОМ — одиночное короткое слово
распознаватель без контекста угадывает и даёт ложные тревоги.

## 8. Что делать дальше

**Четвёртого сплошного прохода не нужно.** Все классы, найденные в блоках
1–14 третьего прохода, закрыты ЗАМЕРАМИ ПО ВСЕЙ БАЗЕ, а не только в
прочитанной зоне.

Если проверять текст ещё — то **не глазами по порядку, а замерами по
признакам, которых пока нет**. Каждая новая примета стоит дороже
прочитанного блока, но ловит по всей базе сразу.

Открытые решения владельца (состав базы, а не текст) перечислены в
`HANDOVER.md`, раздел 7: повторяющиеся заголовки, словоформенные двойники,
несловарные формы, заголовки со слешем, вульгарный регистр.
